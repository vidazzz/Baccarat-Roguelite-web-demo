# 《澳门风云》MVP 游戏设计文档

## 1. 文档信息

- 阶段：玩法验证 / MVP
- 状态：初版
- 核心类型：百家乐、肉鸽成长、轻量模拟经营
- 目标平台：桌面端优先，MVP 以浏览器运行

本文档记录当前已确认的玩法规则。所有具体经济数值均为建议初值，需通过试玩与模拟调整。

## 2. 游戏概念

玩家经营一家能够持续产生收入的餐厅，同时进入不同等级的赌场参与百家乐。玩家观察多张牌桌各自形成的路单，寻找适合自身技能构筑的牌路，下注后通过搓牌亲自揭晓关键牌。

本作世界中，赌徒总结的“路数玄学”是真实规律：特定历史结果会令后续结果发生概率偏移。玩家掌握的技能能够进一步改写开牌概率，因此核心能力不是单纯提高胜率，而是识别局势、选择牌桌并在合适时机承担风险。

## 3. 核心体验

### 3.1 体验支柱

1. **观察与择桌**：多桌同时运行，玩家需要从图形化路单中寻找机会。
2. **概率操纵**：路数和技能真实影响结果，但不保证必胜。
3. **亲手揭晓**：通过搓牌逐步获得信息并释放胜负悬念。
4. **资金取舍**：赌资既可继续下注，也可投入餐厅换取长期收益；走投无路时可以典当家底。

### 3.2 核心体验语句

> 在多张不断变化的牌路中寻找自己最擅长的趋势，用成长出的赌术把玄学变成优势，并不断决定继续下注、带钱离场，还是押上家底。

## 4. 游戏循环

### 4.1 核心赌局循环

```text
选择赌场
  -> 浏览同步运行的牌桌和路单
  -> 选择牌桌
  -> 观察或下注
  -> 封盘后结算路数与技能造成的概率偏移
  -> 按百家乐规则发牌
  -> 玩家搓开关键牌
  -> 结算并更新路单
  -> 留桌、换桌或离场
```

### 4.2 外部资金循环

```text
餐厅周期收益 -> 可用现金 -> 赌局盈利或亏损
       ^                         |
       |                         v
       +---- 投资升级餐厅 <- 离场资金

餐厅典当 -> 获得最后一笔流动资金 -> 继续赌局或彻底破产
```

### 4.3 游戏失败

当玩家失去全部流动资金，且餐厅等可典当财产均已典当后，游戏结束。

完整肉鸽流程的终点暂不定义，不属于本次 MVP 的验证目标。

## 5. 赌场系统

### 5.1 赌场数量

MVP 至少包含两座赌场。赌场大厅使用 2D 图形界面，不制作完整 3D 场景。

| 属性 | 初级赌场 | 高级赌场 |
| --- | --- | --- |
| 定位 | 学习、积累与恢复资金 | 高风险、高资金波动 |
| 建议桌数 | 4 桌 | 6 桌 |
| 最低下注 | 较低 | 较高 |
| 最高下注 | 较低 | 较高 |
| 单次门票 | 100 | 1,000 |
| 视觉风格 | 朴素、信息清晰 | 更华丽但保持可读性 |

玩家每次从赌场选择界面进入赌场时支付一次门票；在该赌场内部往返大厅和牌桌不重复收费。现金不足以支付门票时不能进入。

两个赌场采用相同的标准百家乐赔率。等级差异来自门票、下注上下限、牌桌数量和视觉主题，而非人为提高赔率。

具体金额在经济模型完成后确定。

### 5.2 多桌运行

- 每张牌桌拥有独立的历史结果、路单、下注倒计时和当前局状态。
- 玩家不在场时，牌桌仍持续产生结果。
- 玩家可以在大厅直接比较各桌，但不能在大厅下注。
- 玩家进入具体牌桌后，可以下注，也可以只观看。
- MVP 中所有后台牌桌只进行数据模拟，不渲染后台 3D 牌局。

### 5.3 图形化牌桌选择

赌场大厅中的每张桌以可点击的牌桌单元呈现，至少包括：

- 牌桌图形和桌号；
- 当前状态与封盘倒计时；
- 最低和最高下注；
- 压缩版大路；
- 当前已识别路势的图形提示；
- 进入牌桌操作。

界面的第一目标是让玩家快速扫视和比较多桌，不使用纯文字列表代替牌桌与路单。

## 6. 路单与路势

### 6.1 MVP 路单

MVP 实现以下两类百家乐路单：

1. **珠盘路**：按时间顺序排列每局结果。
2. **大路**：用列结构表现连续同侧获胜与庄闲切换，是技能判断的主要依据。

建议使用行业常见的颜色和符号：

- 红色：庄赢；蓝色：闲赢；绿色斜杠：大路和局叠加标记；
- 大眼仔路为空心圆，小路为实心圆，曱甴路为斜杠。

大厅显示压缩版大路；具体牌桌内使用赌场常见的路纸排版：左侧为珠盘路，右上为大路，右下依次并排显示大眼仔路、小路和曱甴路，最右侧显示牌局统计与庄、闲问路结果。

路纸图标遵循赌场常用表达：大眼仔路使用红、蓝空心圆，小路使用红、蓝实心圆，曱甴路使用红、蓝斜杠。大路中的和局不独立占格，而是在最近一次庄或闲结果的空心圆上叠加绿色斜杠；连续多次和局在斜杠旁显示累计次数。问路区继续使用空心圆、实心圆、斜杠三种对应图标，保证预测结果和实际路纸能够直接对照。

### 6.2 MVP 路势

首版至少支持：

- 长庄：庄连续获胜；
- 长闲：闲连续获胜；
- 单跳：庄闲持续交替。

路势由历史结果触发，并真实改变下一局概率。玩家需要通过游玩学习这些规律。界面可以提示已识别的路势，但不直接替玩家给出下注答案。

## 7. 技能与概率系统

### 7.1 核心原则

最终结果由基础路势偏移与神助共同形成；信心只决定神助是否发动：

```text
基础百家乐概率
  + 当前牌桌的路势偏移
  = 初始牌局分布

下注封盘
  -> 结算下注风险、标记路数、逆势惩罚和连胜
  -> 得到本局信心，即神助触发率
  -> 最后一张牌可能触发神助
  -> 神助小游戏选择低档或高档预测命中概率
```

- 路数在没有技能时也会造成概率偏移。
- 信心只增加神助触发概率，不改变神助发动后的低档、高档概率或改牌效果。
- 概率优势不等于确定结果，玩家始终可能在优势局中失败。
- 已公开的牌永远不能改写；每个发牌阶段的最后一张暗牌允许在神助结算时改写一次。
- 结果生成后，具体牌序必须符合百家乐发牌与补牌规则。

### 7.2 MVP 技能

首版保留三项与基础路势同主题的成长入口：

| 技能 | 主题路数 | 当前 MVP 状态 |
| --- | --- | --- |
| 长庄术 | 连续庄赢 | 可装配、升级，数值效果待接入 |
| 长闲术 | 连续闲赢 | 可装配、升级，数值效果待接入 |
| 单跳术 | 庄闲交替 | 可装配、升级，数值效果待接入 |

具体技能与新增路数类型的对应关系、数值和升级曲线待后续平衡。当前信心验证先以玩家手动标记有效路数为准，技能界面不得暗示技能等级已经修改信心。

- 当前只有一个技能栏位，玩家可以不装备技能，或在技能管理界面切换唯一的已装备技能。
- 技能管理界面提供装配、卸下和升级操作；升级消耗现金，MVP 最高 5 级。
- 当前技能等级保留装配、升级和成长入口，但不直接进入信心或神助效果公式；后续技能与完整路数类型的对应关系另行平衡。

### 7.3 信心与神助

- 每个下注局从 70% 基础信心重新结算，结果限制在 0% 至 100%；调试锁定可以将其设为 100%。
- 下注金额占封盘前流动现金每满 10%，信心增加 5%。餐厅典当价值不计入本次下注占比。
- 珠盘路按六行逐列持续落格；显示区域用满后新起一列，并把较早记录整体向左推出。历史裁剪不得使最后一局固定在某个格位。
- 点击珠盘路始终标记整张珠盘路，无论当前是否形成有效路数。珠盘路使用下一局即将落入的格子作为预测基准：从下一格所在行向左回溯，连续出现 4 个相同结果时形成金刚庄或金刚闲；珠盘路单跳也从该行的下一格向左倒推。
- 除珠盘路上述“下一格所在行”规则外，其他路数都必须以最后一局为终点向前识别连续后缀；历史中较早形成、但没有延续到当前预测位置的图形不参与预测。大路和下三路均可点击起始列，将该列至末列作为观察区间。
- 下三路以红蓝图标识别长路、单跳、逢红/蓝连、逢红/蓝不连和不长过 N 口。成型路数预测的是下一枚红蓝图标，再通过庄问路、闲问路反推唯一对应的下注方向；两边问路颜色相同、无法唯一反推时，不产生信心效果。
- 只有有效标记路数预测方向与押注相同时，才获得每个路数 5% 的加成。
- 标记操作本身不能向正式玩家透露路数是否成立；所有路书无论识别结果都显示相同的标记反馈。玩法验证阶段允许额外显示明确标注为 `DEBUG` 的有效路数、预测方向和失败原因，该信息必须能够在正式版本关闭。
- 每份路书在当前预测位置最多只能成立一个有效路型。识别器可以在内部发现多个重叠候选，但必须按“路书专属型、长路、单跳、逢某方连/不连、不长过 N 口”的顺序归类并只保留一个；更早结束或与最终分类重叠的候选不参与信心结算。
- 标记路数从长度 2 起，每增加一级长度额外增加 2%。长路以 5 局为长度 1、其后每局加一级；单跳以 6 局为长度 1、其后每两局加一级；逢庄/闲连以 4 局为长度 1、其后每局加一级。未单独规定的路数暂按每增加一个确认单位加一级。
- 无论是否标记，只要当前牌桌存在有效路数，押注其预测结果的对家时，每个相反预测路数扣除 5%。押和不触发庄闲路数的增益或惩罚。
- 每延续一局下注连胜增加 1%；和局退注不终止连胜，亏损时归零。
- 前一天下注净盈利时形成天连胜，每连续一个盈利日增加 5%；当前 MVP 的“总体盈利”按已结算赌局净收益统计。
- 旁观局不进行上述信心结算，并使用基础信心。
- 信心只在确认下注、封盘进入牌局时结算并公开。在选择筹码、落注和标记路书期间不预览变化结果。
- 通用路数包括长路、单跳、逢庄/闲连、逢庄/闲不连、庄/闲不长过 N 口；珠盘路单独识别金刚庄/闲和珠盘路庄/闲单跳；大路额外识别 1324 交替和 2121 交替（两房一厅）。不同路书各自识别出的唯一有效路型可以叠加，同一本路书内部不能叠加。
- 初始四张牌的最后一张，以及每一张后续补牌，分别拥有一次神助检查机会。
- 信心值是神助触发概率。旁观局不触发神助。
- 路数只负责预测下一局庄闲走势并形成信心，不参与神助触发后的求牌和喊牌；已下注时，100% 信心必定触发神助。
- 神助的目标恒定为玩家实际下注的结果。玩家押庄就求能令庄胜的牌，押闲就求能令闲胜的牌，押和就求能形成和局的牌。
- 神助触发后进入 3.2 秒点击小游戏；能量顶满采用高档预测命中率，超时采用低档预测命中率。
- 神助小游戏嵌入开牌动画：玩家眯牌约到 32% 进度时暂停触发，荷官翻牌约到 42% 进度时暂停触发。小游戏档位反馈结束后，从暂停位置自动完成剩余开牌动画，再在牌面特写中反馈神助命中或落空。
- 开牌动画暂停后，先播放持续 1 秒的“神助发动”定格反馈，以多段白屏闪切、大字砸入、冲击线和强烈连续屏震表现；该反馈结束后才开始计算小游戏时间。
- 小游戏实时显示气势百分比和剩余时间；结束后明确展示高低档、预测方向和所得概率，等待玩家确认后才继续开牌。
- 点击区域覆盖全屏，文字从实际点击位置爆出。系统枚举当前暗牌所有不改变补牌结构、并能让玩家下注获胜的合法点值：目标点数偏大时喊“吸”，偏小或偏零时喊“吹”，只需要零点公仔时喊“公”，只需要八或九时直接喊点数。喊词只由所求牌值决定，与路数无关。
- 每次点击使用大尺寸砸字、闪光和屏幕震动形成强冲击；气势越接近满格，喊词尺寸、辉光、震幅和移动端触觉反馈越强。
- 小游戏结束后显示取得的概率档位、具体概率和预测方向；玩家确认后才继续开牌，是否命中不提前公开。
- 神助目标牌真正翻开后，必须在当前牌面特写镜头尚未移走时立即显示本次神助概率是否命中。命中与落空使用不同的全屏强反馈，默认停留 1 秒后继续，玩家也可以点击任意位置提前关闭；提示关闭后才执行回桌运镜。
- 神助只能改写当前尚未公开的最后一张牌，且候选牌值必须保持既定补牌结构合法。

### 7.4 待验证规则

以下内容尚未定案：

- 技能全部被动触发，还是包含需要玩家主动发动的强力技能；
- 玩家能否看到精确概率；
- 和局是否接受玩家下注；
- 是否在 MVP 中实现庄抽水、对子等附加规则。

在实现前应为这些规则提供配置能力，避免写死在界面逻辑中。

## 8. 下注与结算

- 玩家进入牌桌后可以下注或旁观。
- MVP 支持庄、闲、和下注，但单轮暂时只允许选择一个下注区域，以保持开牌时的双方归属明确。
- 牌桌排版由上至下固定为荷官侧牌位、闲/和/庄下注区、操作按钮、筹码托盘和完整路单；下注与看路不再分列为两个页面区域。
- 玩家先选择一种筹码面额，再点击下注区域。每点击一次放入一枚当前面额筹码，并立即从可用现金中扣除对应本金；同一区域可以连续叠加。
- 已在某一区域落注后，切换到另一区域前必须先取消当前暂存下注。
- “取消”一次性撤回本轮所有暂存筹码并全额返还本金；“确认”将暂存筹码转为正式赌注并进入发牌。
- 下注金额受当前牌桌上下限和玩家可用资金约束。
- 封盘后不能修改下注。
- 旁观不会进入 3D 牌桌。玩家留在当前下注页，纸牌从荷官侧直接移动到桌面上的闲、庄牌位并自动翻开，不使用运镜。
- 旁观动画先依次发初始四张并逐张翻开；只有初始牌面公开后，才按照真实补牌结果追加“发一张、翻一张”的补牌动画。
- 全部牌面公开后在当前牌桌覆盖显示庄闲点数和胜负，随后更新下方路单；旁观局不触发玩家开牌、咪牌或神助。
- 旁观局同样更新牌桌路单，但玩家身处赌场时餐厅停止营业。
- 正式下注后的 3D 桌面不重复显示押注区，只设置左侧闲家和右侧庄家的发牌放牌区。荷官侧先依次把初始四张牌发到两个桌内牌位，再用纯纸牌位移动画把玩家下注一方的整手牌推到近侧中央；不制作荷官模型。
- 补牌仍先发到所属方的桌内牌位。若补牌属于玩家下注的一方，发牌结束后继续滑到玩家面前，再进入现有的逐张选择开牌流程。
- 荷官开牌时摄像机和观察点沿同一方向平移推进到目标牌，不绕到牌桌另一侧，也不做大角度水平转向。
- 标准赔率及庄家抽水是否完全采用真实百家乐规则，需要在首轮经济模拟前确认。

## 9. 搓牌体验

### 9.1 目标

搓牌是 MVP 中最重要的表现环节。其他场景可以简化，但搓牌必须提供清晰、可控并具有悬念的操作反馈。

### 9.2 基本交互

```text
从长边、左下角或短边附近按住
  -> 按下时吸附并锁定咪牌方向
  -> 沿锁定方向推进或回退
  -> 玩家按下开始咪牌时，手指占位物立即出现并遮住数字与花色
  -> 沿当前折线方向明确拖动，可单独移开手指
  -> 牌角逐渐卷起并露出牌面信息
  -> 推进到总进度 70% 后完全揭牌
  -> 未完成时松手，完全回弹并允许重新选择方向
```

玩家应能够分阶段看到边纹、局部点数和完整牌面，逐步排除可能结果。鼠标拖动距离与露出程度必须稳定对应，不能让随机动画取代操作。

- 三种方向以当前镜头为基准，固定为镜头左侧长边、左下角和靠近镜头的短边；庄闲两侧使用相同的屏幕方向。
- 每个方向拥有宽容的角度判定扇区；点击可以位于牌面之外，只要仍落在有效扇区内就视为选中。
- 按下后角度不再随鼠标横向摆动，垂直于推进轴的移动不改变进度。
- 进入咪牌特写镜头时不显示手指；每次按下开始操作时手指立即出现，随翻起的牌面运动。未完成松手回弹后手指消失，下一次按下重新出现。
- 开牌推进与移开手指使用互相垂直的两条输入轴。长边、左下角、短边三种咪牌方向分别拥有对应的手指移开方向。
- 只有连续移动达到明确距离，且移手指方向的分量显著大于开牌推进分量时，才锁定为移手指操作；锁定期间开牌进度冻结，避免正常咪牌误触。
- 拖动可以随时向前或向后；未完成时松开鼠标必定回到零进度，玩家可不限次数重试。

### 9.3 使用频率

- 普通牌允许点击或短拖快速翻开。
- 影响胜负的关键牌默认进入完整搓牌模式。
- 玩家可以主动选择快速开牌，避免重复操作造成疲劳。
- MVP 可以省略荷官角色和手部骨骼动画。

### 9.4 反馈组成

- 纸牌弯曲与回弹；
- 牌面分阶段显露；
- 接触阴影和轻微桌面反馈；
- 与拖动速度对应的摩擦音；
- 完全揭牌时的明确视听反馈。

### 9.5 实时牌势与末张判势

- 开牌过程中持续显示庄、闲双方当前已公开点数，并标记领先、落后或同点以及点差。
- 当前发牌阶段只剩最后一张暗牌时，按所有真实牌面列出该牌将导致的即时结果：赢、输、和、闲补牌或庄补牌。
- 候选牌按真实牌面显示为 `A、2–10、J、Q、K`；`10/J/Q/K` 明确标为同一组 0 点牌，不再使用单独的“0”牌面代替字母牌。
- 连续牌面得到相同判势时合并为区间，例如 `4–9` 全部导致闲补牌时只显示一个“4–9 · 闲补牌”结果。
- 赢输以玩家当前下注方向为准；旁观时直接显示庄赢或闲赢。
- 判势只允许读取已公开牌和玩家正在揭示的牌位，不得使用其他暗牌的预生成点数。
- 尚有多张暗牌导致结果不确定时不显示确定性结果表。

## 10. 餐厅经营

餐厅完全通过 2D 管理界面呈现，不制作角色移动、装修摆放或生产动画。

### 10.1 功能

1. **升级**：投入现金，提高餐厅等级和周期收益。
2. **周期收益**：餐厅正常经营时，每个经营周期自动产生与等级对应的现金。
3. **典当**：立即获得一笔资金，餐厅停止产生收益。

### 10.2 周期规则

游戏拥有独立的世界时间，用于后续日程、事件和营业安排：

- 每个游戏日固定为 24 小时，跨过 24:00 后进入下一日；
- 赌场外每经过 1 秒现实时间，推进 1 小时游戏世界时间；
- 进入赌场大厅、牌桌或开牌流程后，每经过 1 秒现实时间，推进 1 分钟游戏世界时间；
- 世界时间不会改变牌桌倒计时、动画、神助小游戏等现实计时逻辑；
- 在牌桌上等待玩家操作的阶段暂停世界时间，包括下注、选择开牌方、眯牌、神助操作与确认、结算确认；其他现实计时不暂停；
- 只要玩家尚未进入赌场，未典当的餐厅就保持营业，每累计 1 小时游戏世界时间结算一次当前等级收益；
- 玩家进入赌场大厅后餐厅立即停业，经营周期进度冻结；离开赌场后从冻结进度恢复营业；
- 玩家可以在任意世界时间离开餐厅或其他赌场外界面进入赌场，不设置营业时段限制。

赌场内外的时间流速只服务于世界日程；餐厅收益只累计玩家位于赌场外的游戏时间。

### 10.3 典当规则

- 典当前必须显示立即获得的金额与失去的周期收益。
- 典当后餐厅进入“已典当”状态并停止经营。
- MVP 可以暂不提供赎回，但数据模型必须保留扩展空间。
- 餐厅已典当且流动资金耗尽时触发 Game Over。

## 11. MVP 内容范围

### 11.1 必须包含

1. 两座赌场，建议分别拥有 4 桌和 6 桌。
2. 每桌独立运行牌局、历史结果和状态。
3. 图形化赌场大厅与可选择的牌桌。
4. 珠盘路、大路及大厅压缩预览。
5. 庄、闲下注和旁观。
6. 完整百家乐点数、发牌与补牌规则。
7. 长庄、长闲、单跳三种基础路势。
8. 至少三项对应技能，真实改写结果概率。
9. 关键牌的 3D 搓牌与快速开牌。
10. 餐厅升级、周期收益和典当。
11. 统一资金结算与 Game Over。
12. 概率、路势、技能和牌局结果调试工具。

### 11.2 暂不包含

- 完整肉鸽旅程终点；
- 剧情、NPC 和正式角色成长体系；
- 3D 赌场大厅和后台桌 3D 画面；
- 餐厅装修与生产表现；
- 联机、账号和服务端同步；
- 荷官模型和复杂手部动画；
- 正式存档与跨设备同步；
- 移动端适配。

## 12. 验证目标

MVP 需要回答以下问题：

1. 玩家是否愿意在多桌之间观察、比较并换桌？
2. 玩家能否理解珠盘路、大路和三种基础路势？
3. 不同技能是否会改变玩家偏好的牌桌和下注行为？
4. 玩家是否相信路势与技能确实生效，同时接受优势局仍可能失败？
5. 搓牌是否比直接翻牌显著增强悬念，且不会在重复使用后造成疲劳？
6. 餐厅是否会产生“投入长期资产还是保留赌本”的真实取舍？
7. 典当餐厅是否成为有压力的最后手段，而非最优常规策略？

建议在试玩中记录换桌次数、观察局数、下注比例、技能触发后的下注变化、快速开牌使用率、餐厅升级时点和典当时点。

## 13. 当前待定事项

- 两座赌场的正式名称、美术主题和具体数值；
- 初始资金、下注上下限和赌场门票的最终平衡；
- 餐厅等级、升级成本、周期长度、收益和典当价格；
- 路势偏移和技能偏移的具体强度；
- 技能触发与叠加规则；
- 和局与对子投注范围；
- 庄家抽水规则；
- 玩家离开赌场时是否存在资金转移限制；
- 单次肉鸽旅程的结构与最终目标。
